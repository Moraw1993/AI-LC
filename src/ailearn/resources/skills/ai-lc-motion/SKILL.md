# Motion explanation

Read shared policy and current Teacher brief. Define one takeaway and a short storyboard:
initial state, two to four transformations, and the final interpretation. Keep narration,
labels and on-screen math synchronized and in the learner's language. Prefer learner
controls (pause, replay, reduced motion), captions and a static equivalent.

Inspect actual harness tools before choosing output. If a video or animation renderer
is available, follow its skill and assemble scenes with verified assets, then render,
preview and check representative frames, duration, numbers, captions and audio sync.
Use image-generation tools only for suitable illustration assets, not exact math labels.

If no video renderer is available, create a standalone HTML/SVG/CSS animation with
play/pause and a static storyboard under `materials/motion/`; describe it as an animation,
not an exported video. If rendering itself is unavailable, provide a storyboard and say
what remains unrendered. Do not install paid services or claim tool executions that did
not happen. Media tools belong to the external harness, not AI-LC's evidence engine.

Show the result, explain each transformation, then ask the learner to predict a new case.
Keep generated assets separate from learner answers. Watching is exposure; assess later
with an unseen task and record any guidance honestly. Preserve learner and existing files.
