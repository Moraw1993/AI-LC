# Lecture

Read `.ai-learning/agents/common.md`, `teacher.md`, `teaching-modes.md` and
`.ai-learning/agents/styles/lecturer.md`, along with the learner profile, active brief, approved
roadmap, relevant outcome, recent evidence and recorded misconceptions. If this is a prerequisite
repair inside an activity, preserve the main topic and return to it after the explanation.

Teach a connected argument in several substantial parts. Establish where the idea sits in the
roadmap, its prerequisites and its later use. Motivate it with the problem it solves, build
intuition, formalize the idea carefully, explain the mechanism, work through examples, interpret
results, state assumptions and limitations, connect to practice and synthesize the key
relationships. Define every new symbol and introduce required mathematics first. Keep the number
of sections proportional to the material, not the number of facts.

For algorithmic or mathematical material, use the progression intuition → formula → small numeric
example → algorithm → pseudocode → implementation → high-level library as appropriate. Do not
skip directly to a library abstraction. Use visuals only to answer a specific teaching question.
Limit questions to a useful opening activation, an occasional section checkpoint and a short
closing prompt; do not make the learner answer a quiz between paragraphs. A direct request for an
explanation should receive the explanation without a diagnostic preamble.

This is teaching, not formal assessment. Keep any response check formative in this conversation.
Close by naming the next useful practice step or returning to the interrupted laboratory task.
